Presets

NE.Standard.UI.Extensions is a package of presets: static classes and extension methods that build the arrangements a screen writes over and over — a header band, a titled section, a list beside the thing chosen in it, a card alone on a page, a message that stays in the page, two fields on one line, a pair of buttons at a form's foot — out of the built-in components. A preset holds a look in one place: where a width, a breakpoint or a spacing has to be chosen, the preset chooses it, so two screens built with it stand alike and an author does not pick one of their own. It adds no component of its own. Each preset returns an ordinary built-in — a stack panel, a container, a card, an expander, a surface, a dialog, a button, a text, a paragraph or a key-value list — so everything they build is already rendered by the platform, and the package is server-only. A returned component takes the usual Set*, Bind* and On* calls after it, like any other.

It is installed separately:

dotnet add package NE.Standard.UI.Extensions

Like every package here it brings its namespace, NE.Standard.UI.Extensions, as a global using, so nothing below needs a using line; a project that sets NEStandardUIImplicitUsings to false writes its own.

A screen written with them

The same form without presets is a tree of stack panels, spacings and placements. With them it reads as the page it describes: sections down a column, two fields to a line, the address folded away while a box is ticked, and the buttons at the foot.

internal sealed class ShippingView : UIViewBase, IUIViewDefinition
{
    private const string FormId = "shipping";
    private const string SameAddressId = "shipping-same-address";

    public static string ViewKey => "shipping";

    protected override IVisualComponent? CreateHeader()
        => UIPage.Header("Shipping", "Where the parcel goes, and who signs for it.");

    protected override IVisualComponent CreateContent()
        => UILayout.Split(CreateForm(), CreateSummary(), sideSpan: 9);

    private static StackPanelComponent CreateForm()
        => UILayout.Stack(28,
            UIPage.Section("Recipient", null,
                UIForm.Row(
                    new TextInputComponent().SetTitle("First name").SetFormId(FormId).BindValue(nameof(ShippingController.FirstName)),
                    new TextInputComponent().SetTitle("Last name").SetFormId(FormId).BindValue(nameof(ShippingController.LastName))
                )
            ),
            UIPage.Section("Invoice address", "Only when it differs from the delivery address.",
                new CheckboxComponent(SameAddressId)
                    .SetTitle("Invoice goes to the delivery address")
                    .BindValue(nameof(ShippingController.SameAddress)),
                UILayout.Stack(16,
                    new TextInputComponent().SetTitle("Street and number").SetFormId(FormId).BindValue(nameof(ShippingController.Street)),
                    UIForm.Row(
                        new TextInputComponent().SetTitle("City").SetFormId(FormId).BindValue(nameof(ShippingController.City)),
                        new TextInputComponent().SetTitle("Postcode").SetFormId(FormId).BindValue(nameof(ShippingController.Postcode))
                    )
                )
                .ShownWhen(SameAddressId, false)
            ),
            UIButtons.Pair(
                UIButtons.Ghost("Back"),
                UIButtons.Primary("Continue").OnSubmit(FormId, nameof(ShippingController.ContinueAsync))
            )
        );

    private static CardComponent CreateSummary()
        => UICard.Create("Your order", "Shipped within two working days.", UIDetails.List(
            ("Items", "3"),
            ("Weight", "2.4 kg"),
            ("Delivery", "Standard")
        ));
}

UIPage — the regions of a page

Preset Builds
Header(string title, string? description = null, params IVisualComponent[] trailing) The band a page is headed by: the title, a muted line under it, and whatever is passed as trailing (a theme switcher, the signed-in person, the page's buttons) at the far end of the title's row — on a phone, buttons with words (ButtonComponent with a title) stand on a row of their own under the line, at the far edge, since two of them beside the title left it a few letters a line; icons stay on the title's row. From the medium breakpoint the title is in the display role on one line and the line runs to three lines under the title's columns. On a phone (below the medium breakpoint) the title is a title's size and wraps under itself between words when it is too long for its row (a single word longer than the row ends in an ellipsis, never breaks), its first line level with the far end, and the line is one line, cut — its whole words its tooltip, a long press away — under the whole band — so the band stays about a title's height (74 px at 390 px with two switchers) and leaves the screen to the page; its top padding there puts the title on the middle of the shell's drawer toggle. Keep a phone's far end to two or three controls: whatever it takes, the title gives up. Returns a ContainerComponent, usually from CreateHeader().
Header(IVisualComponent leading, string title, string? description = null, params IVisualComponent[] trailing) The same band led by an action before the title — UIIconButtons.Back() on a page reached from another — on the title's row at every width; the title and the line start after it, and its glyph stands on the content's 24 px edge. On a phone it follows the shell's drawer toggle where the view has one: the toggle, a step of 8 px, Back, then the title. The leading action comes first in the band's order, so the keyboard reaches it before the far end.
BoundHeader(IVisualComponent? leading, string titlePath, string? descriptionPath = null, params IVisualComponent[] trailing) The band with a title and a line the controller holds — a note's name, its status — bound at the two paths (the phone's cut line's tooltip too), led by leading where one is given.
Header(UIHeaderSize size, IVisualComponent? leading, string title, string? description = null, params IVisualComponent[] trailing), BoundHeader(UIHeaderSize size, …) UIHeaderSize.Strip is a panel's caption over the list or the tree in it — an explorer's "Files": the name a muted label (the overline role), set in by a row's 8 px so it stands over the rows' words, the far end's icon buttons on its row. UIHeaderSize.Page is the band above. UIHeaderSize.Pane is the title row of a pane beside a list or a tree — a conversation's, an open note's — the same at every width: the name one line in the subtitle role, cut with its whole words as its tooltip; the description a muted caption beside it (a status: "Not saved"); the far end on the same row; no edge of its own, the pane's padding being it. leading stands before the name: UIIconButtons.Back().ShownBelow(UIResponsiveTier.Md) where a phone has no list beside the pane, a round picture (an ImageComponent with UIImageShape.Circle, 32 px, the person glyph where it has no picture), or both in a UILayout.Row. A bound name is the thing's own words, never looked up as a key; a bound caption may be a key ("Not saved" in the reader's language).
Section(string title, string? description, params IVisualComponent[] content) A titled part of a page: the heading, an optional muted line, and the content below it. The heading and its note sit closer to each other than to the content; a long title wraps.
Heading(string title, string? description = null, params IVisualComponent[] trailing), Section(IVisualComponent heading, params IVisualComponent[] content) A section's heading with things at its far end — the + that adds to the list under it, a menu, a sample's source — the title and its line taking the rest of the row (UILayout.Ends); Section(heading, …) stands it over the content.
Fold(string? title, bool expanded, params IVisualComponent[] content) The collapsible sibling of Section: the quiet expander (UIExpanderVariant.Quiet) — the name a muted caption with the chevron after it, no card — over the content in a stack 12 px apart, open or folded to begin with. For the advanced part of a form, a step of a narrow panel, a model's thinking under a message. Returns the ExpanderComponent: .BindExpanded(path) follows the controller, ConfigureDefaultHeader(header => header.SetIcon(…)) adds a mark, and a null title leaves the name to a binding — ConfigureDefaultHeader(header => header.BindTitle(path)).
Labelled(string label, IVisualComponent content, bool wrap = false) A component under an overline label: a value, a sample, a control with no title of its own. The label keeps one line; wrap lets a label that is a sentence run on.
Empty(string icon, string title, string? line = null, IVisualComponent? action = null) Where something would be and nothing is yet — a pane before a row is chosen, a page with nothing made: the list's own empty state, the same component (DefaultEmptyTemplate: the icon in the brand's colour, the body title in the text's own ink, the muted caption under it, both wrapping), action under the words, the block in the middle of the room it is given (a ContainerComponent as tall as its parent). No surface of its own.
Outcome(string? icon, UIMessageSeverity tone, string title, string? line, params IVisualComponent[] actions), Outcome(…, ParagraphComponent? line, …) What came of a press, in place of the form it ends — "Check your inbox", "Order placed", "Not for this account": a raised panel, 24 px in, the mark in the tone's colour (icon, else the tone's own) before the title in the title role, the line a muted caption under it (bound in the second overload), and the ways on at the far end, the safe one first, wrapping as UIButtons.Pair does. A status to a screen reader, an alert for Warning and Danger, so it is read as it replaces the form. One on an empty page is UICard.Centered(outcome).
Band(IVisualComponent content) A band across the content in the brand's faint tint (UISurfaceStyle.Tinted), 16 px in and 12 down: the filters over a list, the question at an article's foot.
Column(UIColumnWidth width, IVisualComponent content) The content kept to a column from the content's edge, however wide the page: UIColumnWidth.Reading (720 px — an article, a settings page of cards), Form (440 px — a short form; UICard.Centered and UIDialogs.Form take it) or Wide (1080 px — a form beside its summary). One of three, never a width of the page's own.
Banner(SurfaceComponent message) A message from UIMessage laid across the top of the content: edge to edge, square, a rule under it, its mark in line with the header's name. Make it the content's first child, outside any padding of the content's own; it scrolls with the page. In the header region of a view with StickyHeader it stays as the page scrolls — on a phone it stands beside the drawer toggle there, and a tall one takes the screen from the page. 
protected override IVisualComponent? CreateHeader()
    => UIPage.Header("Projects", "Everything the team is building.", new ThemeSwitcherComponent());

A page reached from another leads its header with Back. NavigateBackEffect is the browser's own Back where a page of this site stands behind, and its fallback address where none does — a bookmark, a link from elsewhere; it runs in the press, with no round trip (interactions and effects). Where back means a place of the application's — the tree a note was opened from — give the button a command instead.

protected override IVisualComponent? CreateHeader()
    => UIPage.BoundHeader(
        UIIconButtons.Back().InteractOn(EventNames.Click, new NavigateBackEffect("/notes")),
        nameof(NoteController.Name),
        nameof(NoteController.Status),
        UIIconButtons.Delete().OnClick(nameof(NoteController.Delete))
    );

A pane's row is the same call at UIHeaderSize.Pane:

UIPage.BoundHeader(
    UIHeaderSize.Pane,
    UIIconButtons.Back().ShownBelow(UIResponsiveTier.Md).OnClick(nameof(NotesController.BackToTree)),
    nameof(NotesController.NoteName),
    nameof(NotesController.Status),
    UIIconButtons.Share().OnClick(nameof(NotesController.Share)),
    UIIconButtons.Save().OnClick(nameof(NotesController.Save))

UIMessage — a message that stays in the page

A toast leaves on its own and a validation line belongs to one field; a message the page keeps until it is no longer true — "Your trial ends in 3 days", "This workspace is read-only during maintenance", "2 errors in the form below" — is a UIMessage. It returns a SurfaceComponent drawn Tinted in the palette's colour for its severity, holding the severity's mark, a title, a body, an optional action and an optional ×.

Preset Builds
Info, Success, Warning, Danger (UIPhrase? title, UIPhrase? body = null, ButtonComponent? action = null, bool dismissible = false) A message in that severity. A title, a body or both: a message with neither throws.
Create(UIMessageSeverity severity, UIPhrase? title, UIPhrase? body, ButtonComponent? action = null, bool dismissible = false, string? icon = null) The same with the severity as an argument, and icon in place of the severity's mark.
Create(UIMessageSeverity severity, TextComponent? title, ParagraphComponent? body, …) The title or the body as a component of your own — bound to the controller, for words that change. The preset gives it the message's role and ink.
Severity Colour Mark To a screen reader
Info UIColorStyle.Info UIGlyphs.Info role="status": read when it is free
Success UIColorStyle.Success UIGlyphs.CheckCircle role="status"
Warning UIColorStyle.Warning UIGlyphs.Warning role="alert": read at once
Danger UIColorStyle.Danger UIGlyphs.Error role="alert"
  • The marks are the framework's own glyphs, drawn with no icon pack installed; icon takes any pack's name instead.
  • The role is the surface's LiveRegion (UILiveRegion.Status or Alert), so a message shown later — its Visibility bound — is read out as it appears, and a bound title or body as it changes. SetLiveRegion(null) on the result takes the role off a message that should only be read where the reader reaches it.
  • The action is your button, with its own command. It stands at the message's bottom end, as a toast's does: from the medium breakpoint beside the words, level with their last line; on a phone under them. An outlined one (UIButtons.Outline) reads on every tint.
  • The × hides the message in the browser through one interaction from its click to the message's Visibility — nothing is sent, so a reload shows it again. The keyboard's focus goes on to the next control after the message, so a screen reader keeps its place. Its name is the framework's word "Dismiss" (ui.message.dismiss, shipped in Russian and Chinese). A message the server should stop showing binds its Visibility instead.
  • The title is in the subtitle role and the body in the body role, both in the page's own ink, which reads 4.5:1 on every severity's tint in both themes, the mark 3:1 or more.
UIMessage.Warning("Your trial ends in 3 days", "Billing starts on the 14th.",
    UIButtons.Outline("Upgrade").OnClick(nameof(BillingController.Upgrade)),
    dismissible: true)

A verdict the server gives, read out as it arrives:

UIMessage.Create(UIMessageSeverity.Success, null, new ParagraphComponent().BindDescription(nameof(CheckoutController.PromoVerdict)))
    .BindVisibility(nameof(CheckoutController.PromoAppliedVisibility))

Preset Builds

Content(string key, string title, IVisualComponent content, string? icon = null) The header over the content, for a dialog that sets more of its own: new UIDialog { Key = …, Label = …, Content = UIDialogs.Content(…), Width = … }.

| Form(string key, string title, string? description, IVisualComponent content, ButtonComponent safe, ButtonComponent primary) | A form in a dialog — rename it, invite someone, change a password: the title in the title role and an optional muted line under it, the content, and UIButtons.Pair(safe, primary) at its foot, 16 px apart.     .OnClose(nameof(ChatController.CloseEdit))

A confirmation

The question asked before something is done — "Delete this note?" — is the other kind of dialog: no header and no ×, only its question, its words and its answers.

Preset Builds
Confirm(string key, string question, UIPhrase? body, string confirmWord, string confirmCommand, UIButtonType confirmType = Danger, string? cancelCommand = null, ButtonComponent? middle = null) A UIDialog named by its question: the question in the subtitle role, wrapping; its words a body line 8 px under it; 16 px under those, Cancel, middle where given, and the committing button, pushed to the far edge (UIButtons.Pair). null words leave the question alone.
Confirm(string key, string question, ParagraphComponent? body, …) The same with words of your own. The preset gives them the body role and the page's ink.
BoundConfirm(string key, string question, string bodyPath, …) The words the controller holds at bodyPath — a question naming the thing it is about, "Delete «Groceries» and its 12 notes?" — kept as written (AsContent): a name in them is the thing's own, never a key that happens to match it.
  • Cancel is the standard action's word "Cancel" (ui.action.cancel, shipped in Russian and Chinese), a ghost button and the first, where the focus lands as the dialog opens. It closes the dialog on the page as the viewer's close (CloseDialogEffect with RaisesClose) and raises its OnClose, which runs cancelCommand where one is given.
  • Escape is Cancel: it closes the dialog and raises the same OnClose, so a controller hears both alike. A press on the backdrop is no answer and leaves the dialog open (CloseOnBackdrop is off).
  • The committing button is a primary or a danger one (confirmType; any other type throws) in the words given, running confirmCommand. The command closes the dialog itself — CloseDialogEffect(key) among its effects — so a refused one leaves the question standing.
  • A middle answer is your button — "Don't save" for unsaved work — standing between Cancel and the committing one; an outlined one (UIButtons.Outline) reads as the other way.
  • The measures are the framework's own leave dialog's, so an application's question and the framework's read alike.
protected override IReadOnlyList<UIDialog> CreateDialogs()
    => [
        UIDialogs.BoundConfirm(
            "delete-note",
            "Delete this note?",
            nameof(NotesController.DeleteQuestion),
            "Delete",
            nameof(NotesController.DeleteNote)
        ),
        UIDialogs.Confirm(
            "unsaved",
            "Save your changes?",
            "They are lost if you leave without saving.",
            "Save",
            nameof(NotesController.SaveAndLeave),
            UIButtonType.Primary,
            cancelCommand: nameof(NotesController.Stay),
            middle: UIButtons.Outline("Don't save").OnClick(nameof(NotesController.DiscardAndLeave))
        )
    ];

UIText.Quote — a quote

A quote as a messenger draws a reply or an edit: a 3 px stroke at its start in an accent colour, a title as a caption in that colour — who wrote it, or "Editing" — and one muted line under it, the start of the words, cut with an ellipsis. It returns a SurfaceComponent with no fill of its own, so it stands on whatever holds it, a message's tint included.

Preset Builds
Quote(UIPhrase title, UIPhrase line, UIThemeColor? accent = null, string? clickCommand = null, string? closeCommand = null) A quote in accent, or in the brand (UIThemeColor.Primary) where none is given.
Quote(string titlePath, string linePath, UIBindingScope scope, string? accentPath = null, string? clickCommand = null, string? closeCommand = null) The same bound to what the controller holds — a reply line over a composer, a quote in a message's row — its colour at accentPath where one is given, the brand while that is null.
  • The title and the line are content: a person's name and words are shown as written, never looked up as a key. A UIPhrase.Of(key) — "Editing" in the reader's language — is still translated.
  • clickCommand makes the whole quote pressable, by the keyboard too, with a press's wash — a jump to the message it quotes. A jump that names what it quotes takes its argument on the result instead: .SetClickable(true).OnClick(command, arguments).
  • closeCommand ends the quote in an × — UIIconButtons.Close(), named "Close" (ui.action.close) — for the reply line the reader can drop. A press on the × is the ×'s alone, never the quote's.
  • The stroke is as wide as a Markdown display's blockquote (the CodeInput package), so a quote in a message and the reply over it are drawn alike.
// Over the composer: who is answered, the start of their words, and an × that drops the reply.
UIText.Quote(nameof(ChatController.ReplyTitle), nameof(ChatController.ReplyLine), UIBindingScope.Root, closeCommand: nameof(ChatController.CancelReply))
    .BindVisibility(nameof(ChatController.ReplyVisibility))

// Inside a message's row: in its author's colour, pressed to go to the message it quotes.
UIText.Quote(nameof(MessageItem.ReplyAuthor), nameof(MessageItem.ReplyLine), UIBindingScope.Relative, nameof(MessageItem.ReplyAccent))
    .SetClickable(true)
    .OnClick(nameof(ChatController.JumpToAsync), UIAction.ArgRelative("id", nameof(MessageItem.ReplyId)))

UIText.Person — a person

Preset Builds
Person(string? avatar, UIPhrase name, UIPhrase? line = null, UIPersonSize size = Medium) A person as a list's row or a byline shows one: the round picture (the person glyph where avatar is null or fails), and 12 px after it, on its middle, the name in the body's role over a muted caption — a role, how long ago, the last words. Both are content, a person's own words as written; a UIPhrase.Of key still translates. The picture has no words of its own for a screen reader: the name stands beside it.
Person(string avatarPath, string namePath, string? linePath, UIBindingScope scope, UIPersonSize size = Medium) The same bound to what the controller holds — a chat's row (UIBindingScope.Relative), the person a conversation is with.

Two sizes, never one a page picks: UIPersonSize.Medium (40 px — a list's row, a byline) and Small (32 px — a dense row, a menu, a table's cell). A pane's title row with a person in it is UIPage.Header(UIHeaderSize.Pane, …) with the round picture as its leading.

.SetTemplate(UILayout.Ends(

    new TimestampComponent().BindValue(nameof(ChatItem.At), UIBindingScope.Relative).SetFormat(UITimestampFormat.Relative)

UIForm — the parts of a form besides its fields

Preset Builds
Field(IVisualComponent input, string hint) The input with a muted, wrapping hint under it: what may be typed, what it is for. The hint starts where the field's words do — under a switch or a checkbox, with its label's words past the box, never under the box's edge.
Row(params IVisualComponent[] fields), Row(double spacing, params IVisualComponent[] fields) Fields side by side in equal columns — a city and its postcode, a first and a last name — their tops level, so a field that grows a validation line does not move its neighbour; 16 pixels apart unless spacing says otherwise. Among fields with a caption over their boxes, a control with none — a switch, a checkbox, a button — stands a caption line down, centred on a box of their size, while they stand side by side. 
UIForm.Field(new TextAreaComponent()
    .SetTitle("Invoice note")
    .SetMaxLength(200)
    .BindValue(nameof(CheckoutController.InvoiceNote)),
    "Printed on every invoice, two hundred characters at most.")

Row divides the twenty-four columns of the placement grid evenly, so it takes two, three, four or six fields and throws for any other count. It is UILayout.Columns(spacing, UIAlignment.Start, fields) underneath, so on a narrow screen the fields stand one under another, as below. A row of fields is UIForm.Row rather than UILayout.Columns, which centres a field against a taller neighbour. A captionless control's cell gets StackPanelComponent.AlignWithFieldBoxes from the width the cells stand side by side at (md, xl for four or six), at the captioned fields' Size — UIFieldBoxAlignment.Small, Medium or Large, medium where they differ; stacked, the control stays where it is. A panel of one's own takes the same property per width, drawn as its top padding and least height, which an authored Padding or MinHeight replaces:

new StackPanelComponent()
    .SetAlignWithFieldBoxes(UIResponsive<UIFieldBoxAlignment>.Create(UIFieldBoxAlignment.None, md: UIFieldBoxAlignment.Medium))
    .AddChild(new SwitchComponent().SetTitle("Remember me"))

UILayout — the arrangements

Preset Builds
Stack(double spacing = 12, params IVisualComponent[] children) Children down a column with the same spacing between each pair.
Row(double spacing = 8, params IVisualComponent[] children) Children along a row, wrapping onto the next line when the row is too narrow.
Columns(double spacing = 16, params IVisualComponent[] children) Children in equal columns — two, three, four or six of them; any other count throws.
Columns(double spacing, UIAlignment? cellAlignment, params IVisualComponent[] children) The same, every cell standing at cellAlignment — UIAlignment.Start holds the cells by the top, as UIForm.Row does; null lets each cell take its child's own.
Split(IVisualComponent main, IVisualComponent side, int sideSpan = 8, double spacing = 24) A main part with a side part to its right, the side taking sideSpan of the twenty-four columns.
Sidebar(IVisualComponent side, IVisualComponent main, int sideSpan = 8, double spacing = 24) The other way round: the side part first (a list, a tree, a filter rail), the main part beside it.
Ends(IVisualComponent start, params IVisualComponent[] end) Something at the start of a row and things at its far end — a title and its buttons, a line and its action, a search and its Add: the end as wide as it is (an Auto column), never half the row, the start the rest, both on the row's middle, 12 px apart and the end's things 8 px apart. On a phone buttons with words stand under the start at the far end, as a page header's do; icons and the rest keep the row.
Board(IVisualComponent[] start, IVisualComponent[] end, double spacing = 16) Cards on two columns, each a stack read top to bottom — a settings page's panels, an account's — held by their tops, spacing apart down a column and across; below xl the columns stand one under the other, the start's first. Either column empty throws.
Panes(IVisualComponent list, IVisualComponent detail, string listVisibilityPath, string detailVisibilityPath, IVisualComponent? placeholder = null, string? placeholderVisibilityPath = null, string? splitPositionPath = null) A list and the thing chosen in it — chats and a conversation, a tree and a note, mail and a message: side by side from md, the list 280 px wide and 16 px of air; with splitPositionPath a GridSplitterComponent between them, its position bound, the list from 200 to 480 px. Below md one at a time, in one cell: the detail in the list's place once it is in front. A placeholder (UIPage.Empty) stands in the detail's place while nothing is chosen.

Each of Columns, Split and Sidebar stands its parts one under another on a narrow screen: two or three columns go side by side from the md tier, four or six columns, a split and a sidebar from xl. Side by side, a part keeps its own VerticalAlignment against a taller neighbour — a text, an input or a button is centred by default — and one that must stay at the top says SetVerticalAlignment(UIAlignment.Start).

Panes leaves which pane shows to the controller, which holds a responsive visibility for each at the paths it is given — UILayout.PanesListVisibility(detailInFront), PanesDetailVisibility(detailInFront, chosen) and PanesPlaceholderVisibility(chosen) give the values, so the breakpoint is the preset's alone. The detail brings its own way back, shown on a phone only:

.SetHeight(UILayoutLength.Fill())

UIText — a line in its role

Display, Title, Subtitle, Body and Caption take (string title, string? description = null) and return a TextComponent in that role. Label(string label) is the muted overline a thing is labelled by. Paragraph(string text) is prose that wraps, and Note(string text) a muted caption that wraps — the line under a heading that explains rather than names; both return a ParagraphComponent. A heading keeps one line and ends in an ellipsis, and so does its description: a TextComponent is a label, so SetWrapMode(UITextWrapMode.Wrap) lets its description run on and SetTitleWrap(true) its title — a heading in prose, an article's headline. A card's and an expander's default header wrap their description on their own.

The same roles exist as extension methods on any text component, for a text that is bound rather than written: AsDisplay(), AsTitle(), AsSubtitle(), AsBody(), AsCaption(), AsOverline(), and Muted(), which puts both lines in the muted colour.

UILayout.Stack(4,
    UIText.Title("Storage"),
    new TextComponent().AsCaption().Muted().BindTitle(nameof(AccountController.StorageLine))
)

UIDetails — names and values to read

UIDetails.List(params (string Key, string Value)[] rows) is a KeyValueActionComponent without the action column or a border of its own — an order's summary, a record's facts — for a card or a surface to hold. Rows are keyed by name, so a list that repeats a name throws.

UIDetails.List(("Plan", "Standard"), ("Region", "Europe West"), ("Billed", "Monthly"))

For values that change, bind the items instead and build each row with UIDetails.Row(string id, string key, string value), which returns a KeyValueActionItem whose key is in the muted colour:

// Controller
public RecursiveCollection<KeyValueActionItem> Lines { get; } =
[
    UIDetails.Row("plan", "Plan", string.Empty),
    UIDetails.Row("region", "Region", string.Empty)
];

// View
UIDetails.List().BindItems(nameof(CheckoutController.Lines))

The sums under a summary are a line each: UIDetails.Amount(string label, string valuePath) — the name muted at the start, the amount the controller holds at the far end, as wide as it is, one line at every width — and UIDetails.Total(string label, string valuePath), the line they come to, both in the subtitle role.

UILayout.Stack(12,
    UIDetails.Amount("Subtotal", nameof(CheckoutController.SubtotalLine)),
    UIDetails.Amount("VAT, 21%", nameof(CheckoutController.VatLine)),
    UIDetails.Total("Total a month", nameof(CheckoutController.TotalLine))
)

Shown on one side of a breakpoint

ShownBelow(UIResponsiveTier tier) shows any component below the tier and collapses it from there on — a Back that a phone needs and a desktop, with the list beside the pane, does not; a drawer's toggle — and ShownFrom(tier) is the other way round. Both set Visibility, so they replace a visibility set before them.

Shown, hidden or enabled by another component

ShownWhen, HiddenWhen and EnabledWhen extend any component and watch the value of another one, named by its component id — so the source is created with an id (new CheckboxComponent(SameAddressId)). Each is one Interact (see interactions and effects), so the rule runs in the browser without a round trip to the server.

Call Holds while
ShownWhen(sourceId) / HiddenWhen(sourceId) / EnabledWhen(sourceId) The source has a value: a switch on, a box ticked, a select with a choice.
...When(sourceId, object? value) The source's Value equals value.
...When(sourceId, UIProperty source, UIComparisonOperator @operator, object? value) The named property of the source satisfies the comparison.

ShownWhen and HiddenWhen collapse the component when it is not shown; EnabledWhen disables it. The rule follows the reader's own edit of the source as well as a value the server pushes, so a switch turned on reveals its panel at once. It holds from the first paint too: a source the view sets (or leaves at its default) is read as the page is rendered, so a note under a switch that is off arrives hidden; a bound source's rule runs as the page takes its values. The server's own refusals read what the view wrote, never the rule's state.

UILayout.Stack(28,
    new RadioGroupComponent(BilledId)
        .SetTitle("Billed")
        .SetOptions(
        [
            new OptionItem { Id = "direct", Title = "Directly" },
            new OptionItem { Id = "reseller", Title = "Through a reseller" }
        ])
        .BindValue(nameof(SubscribeController.Billed)),
    UIPage.Section("Company address", null, CreateAddress())
        .HiddenWhen(BilledId, "reseller"),
    new CheckboxComponent(TermsId)
        .SetTitle("I accept the terms")
        .BindValue(nameof(SubscribeController.TermsAccepted)),
    UIButtons.Primary("Subscribe")
        .EnabledWhen(TermsId)
)
