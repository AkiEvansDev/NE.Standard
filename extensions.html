Presets

NE.Standard.UI.Extensions is a package of presets: static classes and extension methods that build the arrangements a screen writes over and over — a header band, a titled section, a list beside the thing chosen in it, a card alone on a page, a message that stays in the page, two fields on one line, a pair of buttons at a form's foot — out of the built-in components. A preset holds a look in one place: where a width, a breakpoint or a spacing has to be chosen, the preset chooses it, so two screens built with it stand alike and an author does not pick one of their own. It adds no component of its own. Each preset returns an ordinary built-in — a stack panel, a container, a card, an expander, a surface, a status, a dialog, a button, a split button, a menu item, a text, a paragraph, a key-value list or one of its rows — so everything they build is already rendered by the platform, and the package is server-only. A returned component takes the usual Set*, Bind* and On* calls after it, like any other.

It is installed separately:

dotnet add package NE.Standard.UI.Extensions

Like every package here it brings its namespace, NE.Standard.UI.Extensions, as a global using, so nothing below needs a using line; a project that sets NEStandardUIImplicitUsings to false writes its own.

A screen written with them

The same form without presets is a tree of stack panels, spacings and placements. With them it reads as the page it describes: sections down a column, two fields to a line, the address folded away while a box is ticked, and the buttons at the foot.

internal sealed class ShippingView : UIViewBase, IUIViewDefinition
{
    private const string FormId = "shipping";
    private const string SameAddressId = "shipping-same-address";

    public static string ViewKey => "shipping";

    protected override IVisualComponent? CreateHeader()
        => UIPage.Header("Shipping", "Where the parcel goes, and who signs for it.");

    protected override IVisualComponent CreateContent()
        => UILayout.Split(CreateForm(), CreateSummary(), sideSpan: 9);

    private static StackPanelComponent CreateForm()
        => UILayout.Stack(28,
            UIPage.Section("Recipient", null,
                UIForm.Row(
                    new TextInputComponent().SetTitle("First name").SetFormId(FormId).BindValue(nameof(ShippingController.FirstName)),
                    new TextInputComponent().SetTitle("Last name").SetFormId(FormId).BindValue(nameof(ShippingController.LastName))
                )
            ),
            UIPage.Section("Invoice address", "Only when it differs from the delivery address.",
                new CheckboxComponent(SameAddressId)
                    .SetTitle("Invoice goes to the delivery address")
                    .BindValue(nameof(ShippingController.SameAddress)),
                UILayout.Stack(16,
                    new TextInputComponent().SetTitle("Street and number").SetFormId(FormId).BindValue(nameof(ShippingController.Street)),
                    UIForm.Row(
                        new TextInputComponent().SetTitle("City").SetFormId(FormId).BindValue(nameof(ShippingController.City)),
                        new TextInputComponent().SetTitle("Postcode").SetFormId(FormId).BindValue(nameof(ShippingController.Postcode))
                    )
                )
                .ShownWhen(SameAddressId, false)
            ),
            UIButtons.Pair(
                UIButtons.Ghost("Back"),
                UIButtons.Primary("Continue").OnSubmit(FormId, nameof(ShippingController.ContinueAsync))
            )
        );

    private static CardComponent CreateSummary()
        => UICard.Create("Your order", "Shipped within two working days.", UIDetails.List(
            ("Items", "3"),
            ("Weight", "2.4 kg"),
            ("Delivery", "Standard")
        ));
}

examples/DemoApp/Views/Screens/CheckoutView.cs in the repository is a full screen built this way.

UIPage — the regions of a page

A bound twin with things after its paths (trailing, content, actions) has two overloads: one without a scope, reading the controller's paths, and one with UIBindingScope scope after the words' paths, written [UIBindingScope scope,] below — a row's own words in an item template. A twin with nothing after its paths takes scope = Root as an optional parameter.

A page reached from another leads its header with Back. NavigateBackEffect is the browser's own Back where a page of this site stands behind, and its fallback address where none does — a bookmark, a link from elsewhere; it runs in the press, with no round trip (interactions and effects). Where back means a place of the application's — the tree a note was opened from — give the button a command instead.

protected override IVisualComponent? CreateHeader()
    => UIPage.BoundHeader(
        UIIconButtons.Back().InteractOn(EventNames.Click, new NavigateBackEffect("/notes")),
        nameof(NoteController.Name),
        nameof(NoteController.Status),
        UIIconButtons.Delete().OnClick(nameof(NoteController.Delete))
    );

UIMessage — a message that stays in the page

A toast leaves on its own and a validation line belongs to one field; a message the page keeps until it is no longer true — "Your trial ends in 3 days", "This workspace is read-only during maintenance", "2 errors in the form below" — is a UIMessage. It returns a SurfaceComponent drawn Tinted in the palette's colour for its severity, holding the severity's mark, a title, a body, an optional action and an optional ×.

Preset Builds
Info, Success, Warning, Danger (UIPhrase? title, UIPhrase? body = null, ButtonComponent? action = null, bool dismissible = false, string? dismissCommand = null) A message in that severity. A title, a body or both: a message with neither throws.
Create(UIMessageSeverity severity, UIPhrase? title, UIPhrase? body, ButtonComponent? action = null, bool dismissible = false, string? icon = null, string? dismissCommand = null) The same with the severity as an argument, and icon in place of the severity's mark.
BoundCreate(UIMessageSeverity severity, string? titlePath, string? bodyPath, UIBindingScope scope = Root, …) The words the controller holds, for words that change: bound as its own words and drawn plain — data, never markup (a path holding a UIPhrase still translates) — in the message's role and ink.
Create(UIMessageSeverity severity, TextComponent? title, ParagraphComponent? body, …) A title or a body of your own beyond words alone — a body with a link or an emphasis; the preset gives it the message's role and ink.
Severity Colour Mark To a screen reader
Info UIColorStyle.Info UIGlyphs.Info role="status": read when it is free
Success UIColorStyle.Success UIGlyphs.CheckCircle role="status"
Warning UIColorStyle.Warning UIGlyphs.Warning role="alert": read at once
Danger UIColorStyle.Danger UIGlyphs.Error role="alert"
  • The marks are the framework's own glyphs, drawn with no icon pack installed; icon takes any pack's name instead.
  • The role is the surface's LiveRegion (UILiveRegion.Status or Alert), so a message shown later — its Visibility bound — is read out as it appears, and a bound title or body as it changes. SetLiveRegion(null) on the result takes the role off a message that should only be read where the reader reaches it.
  • The action is your button, with its own command. It stands at the message's bottom end, as a toast's does: from the medium breakpoint beside the words, level with their last line; on a phone under them. An outlined one (UIButtons.Outline) reads on every tint.
  • The × stands on the words' first line, its glyph on the message's far edge as the mark stands on the near one; the stylesheet sets the first line on the small × button's middle, whatever line the theme gives the title or the body.
  • The × hides the message in the browser through one interaction from its click to the message's Visibility — nothing is sent, so a reload shows it again. The keyboard's focus goes on to the next control after the message, so a screen reader keeps its place. Its name is the framework's word "Dismiss" (ui.message.dismiss, shipped in Russian and Chinese). A message the server should stop showing for good takes a dismissCommand: the × still hides it at once, and runs the command beside the hide, where the controller records the choice and keeps its bound Visibility collapsed.
  • The title is in the subtitle role and the body in the body role, both in the page's own ink, which reads 4.5:1 on every severity's tint in both themes, the mark 3:1 or more.
UIMessage.Warning("Your trial ends in 3 days", "Billing starts on the 14th.",
    UIButtons.Outline("Upgrade").OnClick(nameof(BillingController.Upgrade)),
    dismissible: true)

A verdict the server gives, read out as it arrives:

UIMessage.BoundCreate(UIMessageSeverity.Success, null, nameof(CheckoutController.PromoVerdict))
    .BindVisibility(nameof(CheckoutController.PromoAppliedVisibility))

UIDialogs — a dialog with a header, a form, and a confirmation

A dialog headed by its mark, its title and an × at the far end, over its content.

Preset Builds
Create(string key, UIPhrase title, IVisualComponent content, string? icon = null, UIColumnWidth? width = null) A UIDialog named by its title, the header over the content; a width keeps the content to that column from the medium breakpoint (Wide, more than a tablet holds, from the extra-large one), the screen's width below. The rest keeps the dialog's defaults: change it with with { CloseOnBackdrop = false }, UIDialog being a record.
BoundCreate(string key, string titlePath, IVisualComponent content, string? icon = null, UIColumnWidth? width = null) The same with the title the controller holds — the thing's name, Add or Edit — bound as its own words (a path holding a UIPhrase still translates); it still names the dialog as it changes.
Content(…), BoundContent(…) The header over the content, for a dialog laid out or set otherwise — a sheet, a height: new UIDialog { Key = key, TitleId = UIDialogs.TitleId(key), Content = UIDialogs.Content(key, title, body), … }.
Header(string key, UIPhrase title, string? icon = null), BoundHeader(string key, string titlePath, string? icon = null) The header alone: the title in the title role with the mark as its own icon, the × at the far end, its glyph on the content's edge. The title carries UIDialogs.TitleId(key), which a dialog built around it names itself by.
CloseButton(string key, UIStandardAction? action = null, UIButtonType type = Ghost) The dialog's own answer that closes it as the viewer does — Cancel, or Close or Done — in the framework's words: the held edits of the dialog's form go back, then the dialog closes on the page and raises its OnClose.
  • A dialog is named by the title it shows (UIDialog.TitleId, aria-labelledby), so a bound title names it as it changes; Label names a dialog with no title of its own. The view does not compile where TitleId names nothing inside the dialog's content, or a component in a template. A dialog stands at the view's root, never in a row, so its Bound* twins bind the controller's paths and take no UIBindingScope.
  • The × closes the dialog as Escape does: on the page, through interactions alone (DiscardFormEffect then CloseDialogEffect with RaisesClose), raising the dialog's OnClose, so a controller that cancels on Escape cancels on the × too. It is UIIconButtons.Close(), named by the standard action's word "Close" (ui.action.close, shipped in Russian and Chinese).
UIDialogs.Create("edit", "Edit message", UILayout.Stack(12, field, UIButtons.Pair(UIDialogs.CloseButton("edit"), save)), AppIcons.Edit, UIColumnWidth.Form)
    .OnClose(nameof(ChatController.CloseEdit))

A form

Preset Builds
Form(string key, UIPhrase title, UIPhrase? description, IVisualComponent content, ButtonComponent primary) A form in a dialog — rename it, invite someone, change a password: the title in the title role and an optional muted line under it, the content, and the standard Cancel (CloseButton) and primary at its foot, 16 px apart. No ×, since Cancel says it; a press on the backdrop loses nothing typed (CloseOnBackdrop is off), Escape closes it. A form's column wide (UIColumnWidth.Form, 440 px) from the medium breakpoint, the dialog's whole width on a phone.
Form(…, ButtonComponent safe, ButtonComponent primary) The same with a safe answer of your own in Cancel's place.
BoundForm(string key, string titlePath, string? descriptionPath, IVisualComponent content, [ButtonComponent safe,] ButtonComponent primary) The title and the line the controller holds — "Add a phrase" or "Edit the phrase", the folder an import goes into — as its own words, the line drawn plain; a title that stays the same is a key the controller holds (a path holding a UIPhrase still translates).
  • The dialog is a form, its key the form's id. Every field of the content with no FormId of its own, written or bound, is given the key, and the primary submits it (its SubmitFormId, unless it already submits another form) — so give the primary its command with OnClick or OnClickShowingLoading. What that does: Enter in a one-line field (one with no OnEnter) commits it and presses the primary; the primary's press judges the fields' Submit rules first and stops on any error, its focus on the first field in error; it waits for the fields' uploads; a field bound OnSubmit holds its value until the press and sends it then, while a field bound two-way still writes as it changes; the fields join one browser form, as a password manager reads them. Cancel puts the held values back and clears what the rules said, so the form opens again untouched.

A confirmation

The question asked before something is done — "Delete this note?" — is the other kind of dialog: no header and no ×, only its question, its words and its answers.

Preset Builds
Confirm(string key, UIPhrase question, UIPhrase? body, UIPhrase confirmWord, string confirmCommand, UIButtonType confirmType = Danger, string? cancelCommand = null, ButtonComponent? middle = null) A UIDialog named by its question: the question in the subtitle role, wrapping; its words a body line 8 px under it; 16 px under those, Cancel, middle where given, and the committing button, pushed to the far edge (UIButtons.Pair). Confirm(key, question, confirmWord, confirmCommand, …) asks the question alone.
Confirm(string key, UIPhrase question, ParagraphComponent? body, …) The same with words of your own beyond words alone — a link to what goes, an emphasis — given the body role and the page's ink.
BoundConfirm(string key, UIPhrase question, string bodyPath, …) The words the controller holds at bodyPath under a written question — "Delete «Groceries» and its 12 notes?" — kept as written (AsContent) and drawn plain: a name in them is the thing's own, never a key that happens to match it, nor markup; a path holding a UIPhrase still translates.
  • Cancel is UIDialogs.CloseButton(key): the standard action's word "Cancel" (ui.action.cancel, shipped in Russian and Chinese), a ghost button and the first, where the focus lands as the dialog opens. It closes the dialog on the page as the viewer's close (CloseDialogEffect with RaisesClose) and raises its OnClose, which runs cancelCommand where one is given.
  • Escape is Cancel: it closes the dialog and raises the same OnClose, so a controller hears both alike. A press on the backdrop is no answer and leaves the dialog open (CloseOnBackdrop is off).
  • The committing button is a primary or a danger one (confirmType; any other type throws) in the words given, running confirmCommand. The command closes the dialog itself — CloseDialogEffect(key) among its effects — so a refused one leaves the question standing.
  • A middle answer is your button — "Don't save" for unsaved work — standing between Cancel and the committing one; an outlined one (UIButtons.Outline) reads as the other way.
  • The measures are the framework's own leave dialog's, so an application's question and the framework's read alike.

A quote as a messenger draws a reply or an edit: a 3 px stroke at its start in an accent colour, a title as a caption in that colour — who wrote it, or "Editing" — and one muted line under it, the start of the words, cut with an ellipsis. UIForm — the parts of a form besides its fields

Preset Builds
Field(IVisualComponent input, UIPhrase? hint = null), Field(IVisualComponent input, ParagraphComponent hint), BoundField(IVisualComponent input, string hintPath, UIBindingScope scope = Root) The input with a muted, wrapping hint under it: what may be typed, what it is for — or the input alone in the same column, so a form writes every field one way; a paragraph of your own (inline links) or the line the controller holds (how much is left), as content. Row divides the twenty-four columns of the placement grid evenly, so it takes two, three, four or six fields and throws for any other count. It is UILayout.Columns(spacing, UIAlignment.Start, fields) underneath, so on a narrow screen the fields stand one under another, as below. A row of fields is UIForm.Row rather than UILayout.Columns, which centres a field against a taller neighbour. A control with no caption stands a caption line down, centred on the fields' box, from the width the cells stand side by side at (md, xl for four or six), at the captioned fields' Size — medium where they differ; stacked, it stays where it is. That is not the row's doing: wherever a control with no caption — a button, an untitled field, a switch, a button group, a panel of them — stands beside a field that is captioned itself, in a horizontal stack of your own that does not wrap or on a grid's row, the framework stands it level with the box, per width as the arrangement turns (AlignWithFieldBoxes, which the compiler sets where you leave it unset). A card, a list or words alone stay put, as does anything beside a whole column of fields or in a wrapping panel of your own, whose later line has no field beside it. UILayout.Row asks for it itself: a thing with no caption stands in a cell whose padding takes the caption's line, on every line, a wrapped one too. A panel takes it as its top padding and least height, anything else as its top margin; with an authored Padding or Margin nothing is implied, and UIFieldBoxAlignment.None keeps a thing where it is laid out:

new StackPanelComponent()
    .SetOrientation(UIOrientation.Vertical, md: UIOrientation.Horizontal)
    .AddChild(new TextInputComponent().SetTitle("City"))
    .AddChild(new ButtonComponent().SetTitle("Find"))

Two more of a panel's own say where what it holds stands beside buttons, both drawn by the stylesheet from its tokens and the theme's lines, never a number of yours: GlyphEdge (UIAlignment.Start or End) hangs the first or last quiet button past the panel's edge, so its glyph or its words stand on the content's edge (an icon by its own IconSize), FirstLineOnControl(UIButtonSize) sets its first child down so that child's first line stands on a button's middle — a name that wraps beside the buttons at its row's end, as a page header's does on a phone — and FirstChildAsCaption stands its first child in a field's caption row, so a label over a control (UIPage.Labelled) stands the control level with captioned fields' boxes.

UIText — a line in its role

Display, Title, Subtitle, Body and Caption take (UIPhrase? title = null, UIPhrase? description = null) and return a TextComponent in that role. Label(UIPhrase? label = null) is the muted overline a thing is labelled by. Paragraph(UIPhrase? text = null) is prose that wraps, and Note(UIPhrase? text = null) a muted caption that wraps — the line under a heading that explains rather than names; both return a ParagraphComponent. Words left out are bound after — UIText.Note().BindDescription(path) — and blank words are refused: null is the one spelling of "none written". A heading keeps one line and ends in an ellipsis, and so does its description: a TextComponent is a label, so SetWrapMode(UITextWrapMode.Wrap) lets its description run on and SetTitleWrap(true) its title — a heading in prose, an article's headline. A card's and an expander's default header wrap their description on their own.

The same roles exist as extension methods on any text component — a template's, one of your own: AsDisplay(), AsTitle(), AsSubtitle(), AsBody(), AsCaption(), AsOverline(), and Muted(), which puts both lines in the muted colour.

UILayout.Stack(4,
    UIText.Title("Storage"),
    UIText.Caption().Muted().BindTitle(nameof(AccountController.StorageLine))
)

Shown on one side of a breakpoint

ShownBelow(UIResponsiveTier tier) shows any component below the tier and collapses it from there on — a Back that a phone needs and a desktop, with the list beside the pane, does not; a drawer's toggle — and ShownFrom(tier) is the other way round. Both set Visibility, so they replace a visibility set before them.

Shown, hidden or enabled by another component

ShownWhen, HiddenWhen and EnabledWhen extend any component and watch the value of another one, named by its component id — so the source is created with an id (new CheckboxComponent(SameAddressId)). Each is one Interact (see interactions and effects), so the rule runs in the browser without a round trip to the server.

Call Holds while
ShownWhen(sourceId) / HiddenWhen(sourceId) / EnabledWhen(sourceId) The source has a value: a switch on, a box ticked, a select with a choice.
...When(sourceId, object? value) The source's Value equals value.
...When(sourceId, UIProperty source, UIComparisonOperator @operator, object? value) The named property of the source satisfies the comparison.

ShownWhen and HiddenWhen collapse the component when it is not shown; EnabledWhen disables it. The rule follows the reader's own edit of the source as well as a value the server pushes, so a switch turned on reveals its panel at once. It holds from the first paint too: a source the view sets (or leaves at its default) is read as the page is rendered, so a note under a switch that is off arrives hidden; a bound source's rule runs as the page takes its values. The server never sees the rule's state, and a property a rule writes closes nothing there: a Subscribe enabled by EnabledWhen(TermsId) takes a press from a page whose terms box is not ticked. The command checks what it needs (TermsAccepted) itself, or the gate is bound to the controller (BindEnabled), which the server reads.
