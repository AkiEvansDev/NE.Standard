Items

An items host is any component that renders a keyed collection through a template: ItemsViewComponent, TableComponent and TreeComponent are the general-purpose ones, and MenuComponent, TabsViewComponent and the SelectComponent/MultiSelectComponent/RadioGroupComponent/SearchComponent inputs are all items hosts too — they add a menu, a tab strip driven by a collection, or options on top of the same collection machinery.

Static vs bound items

SetItems/AddItem/AddItems hold a plain, author-declared list — data that never changes per session and renders fully on the server, cached alongside the view itself:

new TableComponent()
    .SetItems(DemoDeploymentRow.CreateDeployments())
    .AddTextColumn("Service", nameof(DemoDeploymentRow.Service));

BindItems(path, scope) points the collection at a RecursiveCollection on the controller instead. It is generated for every items host from the Items property, so its scope defaults follow the same rule as any other binding — Root unless you pass Relative.

new ItemsViewComponent()
    .BindItems(nameof(SomeController.Rows))
    .SetTemplate(rowTemplate);

A closed list of options shown by several selects is a static list given to SetOptions (AddOptions, a menu's SetItems): the component keeps its own references and nothing takes the items over, so one static readonly list is shared freely by every select, radio group, menu and page. A list the controller holds is a recursive tree with one owner per node: putting one node in a second place is refused, and the refusal names both places — each path from its root, and the root's type.

Every item is keyed

An item collection — static or bound — must hold IBindableItems, each with a stable string Id; the compiler refuses anything else. Wrap a plain value with UIValueItem<T>, whose Id is derived from the value itself (so the same value cannot appear twice), or UIOptionValue<T>, which also fills Title so Select/MultiSelect/Search/RadioGroup render options with no template of their own. Id is declared [RecursiveMember(false)] — it registers a path segment but generates no setter, because a notifying Id would let an item be re-keyed after insertion and orphan every path built from the old key.

The built-in row shapes: TextItem, OptionItem, MenuItem, TabItem, BadgeItem, ButtonItem, TreeNode, KeyValueActionItem, BreadcrumbItem. Every styling property on them starts null, so an item says only what its author gave it and falls back to the template drawing it; Visibility and Enabled are the exception and default to Visible/true. What an item leaves null, and an empty collection, does not travel at all — at every depth of the item, in the page and over the hub alike — and the page reads a property an item does not carry as null; a false, a zero or any other value set travels as it is.

Item templates

SetTemplate/AddTemplateVariant (declared on ItemsComponentBase<TComponent, TItem, TTemplate>) set the default template and named variants; TemplateKeyProperty (on TemplatedComponentBase) names the item property whose value picks a variant by name — MenuItem.Kind choosing between the header, separator, check, select and plain entry templates is the built-in example. FallbackTemplateKey names the variant used when the value names none. Patching the property named by TemplateKeyProperty re-renders that one item through a collection Replace, so any client-side state the row held is gone — that is the mechanism, not a bug.

Inside a template, bindings default to Root like everywhere else — .BindTitle(path, UIBindingScope.Relative) is what reaches the item's own properties, and it is almost always what you want inside a row:

new StackPanelComponent()
    .AddChild(new TextComponent()
        .BindTitle(nameof(DemoRowItem.Title), UIBindingScope.Relative)
    );

There is no "current item index" argument — an item is addressed by key. UIAction.ArgCurrentItemKey(name) and UIAction.ArgCurrentItem(name) pass the row's key or the row itself as a command argument:

.OnRowClickWithItemKey(nameof(Controller.OpenRow))

RowItemsComponentBase<TComponent, TItem, TRow> (the base of TableComponent, TreeComponent and KeyValueActionComponent) wraps the whole row in a TRow — DefaultRowTemplate for all three — and exposes OnRowClick/OnRowClickWithItem/OnRowClickWithItemKey (a press, or Enter or Space on the keyboard's row), OnRowOpen/OnRowOpenWithItemKey (Enter after the click, or a double click) and OnRowRemove/OnRowRemoveWithItemKey (Delete on a removable row). ItemsViewComponent carries the parallel vocabulary directly — OnItemClick/OnItemClickWithItem/OnItemClickWithItemKey, OnItemOpen/OnItemOpenWithItemKey and OnItemRemove/OnItemRemoveWithItemKey — so a plain list, a table and a tree all raise a row's click, open and remove the same way. An item event is kept by its host and written on the template in its slot and on every one set there later, so OnItemClick and SetTemplate (or OnRowClick and SetRowTemplate) may come in either order; the same event registered twice, the later wins. It reaches its own slot only: OnItemClick never reaches a variant AddTemplateVariant sets, except a menu's, which names its check entry too.

What a row carries

The page is sent each row's item kept to what its host reads off it: the properties its templates bind (a nested row's Parent-scoped bindings included), its filter and sort rules, its template key, the key, Group, IsContent and the abilities. A nested list nothing of the row reads is not in it — a list bound inside the row's template gets it as its own rows — and a value that reads the same as an absent one (false under a binding that falls back to false, an ability's true) is left out. A chat list's row whose model holds every message of the conversation is sent its name, its last line and its time.

Code of your own in the browser that reads a row's item past its templates (rows.itemOf in a package's engine) names what it reads, or takes the item whole:

new ItemsViewComponent()
    .BindItems(nameof(Controller.Rows))
    .AddItemReads("Owner.Email", "Score")
    .SetTemplate(new TextComponent().BindTitle(nameof(Row.Title), UIBindingScope.Relative));

new ItemsViewComponent()
    .BindItems(nameof(Controller.Rows))
    .ReadsWholeItems();

In development the page warns, naming the host and the path, where it reads a property a row was not sent. A chart, a layered graph, the DataGrid and any host that draws no rows of its own are sent their items whole.

Grouping, filtering and sorting

GroupedItemsComponentBase adds SetGroupTemplate for a header drawn above each group of items that share IBindableGroup.Group. The header is drawn from the first shown row of its group — its bindings read that row, and a group all of whose rows a filter hides has no header. A command on the header learns which group it heads with UIAction.ArgGroupKey(name), resolved on the server; ArgCurrentItemKey there is the key of the row the header stands in. A windowed host groups too, by neighbours rather than buckets: a row whose group differs from the row before it gets a header, so a chat feed read backwards shows a day's header over the first message of each day. A header stands where its own HorizontalAlignment puts it, as a row does: a day's pill set to Center sits in the middle. ScrollToItemEffect(listId, key) from a command shows a row at the top of the list, its header over it — the first message of a day the command read the window at. FilterBy and SortBy (on ItemsComponentBase) add rules evaluated against an item property:

.FilterBy(filterBoxId, IInputComponent.ValueProperty, nameof(DemoDeploymentRow.Service))
.SortBy(nameof(ITabItemModel.Order))
  • FilterBy(source, itemProperty, operator, activeOperator, activeValue) ties a filter to another component's property (or, with no source, to a constant); the default operator is UIComparisonOperator.LikeIgnoreCase.
  • SortBy(source, itemProperty, direction, activeOperator, activeValue, priority) — several sorts combine by ascending priority.
  • With no source, both are unconditionally active.

They compile onto UIItemsView (_filters/_sorts) and run client-side on a plain or virtualized host — filtering hides rows via a class rather than removing them, and fails open: an item whose value never reached the client stays visible rather than silently disappearing. A windowed host resolves rules on the server instead (see below), because the client only ever holds one window of a source that may hold thousands.

Selection

ISelectableItemsComponent (implemented by ItemsViewComponent, TableComponent, TreeComponent) adds:

  • SelectionMode — None (default), One, Many.
  • SelectedKey — two-way, the chosen key under One.
  • SelectedKeys — two-way, the chosen keys in choice order under Many.
  • ISelectionStyleComponent.SelectionStyle — what a chosen row looks like; unset parts fall back to the control's own default.

From the keyboard an items view and a table are one stop of the Tab order: the host keeps the focus and names the keyboard's row (aria-activedescendant), lit only while the keyboard holds it. The arrows walk the rows (a horizontal list Left and Right, a wrap by its lines), Home and End go to the ends, Page Up and Page Down a viewport's height. Enter runs the row's click and then its open; Space chooses where the host chooses and otherwise runs the click. A single choice follows the arrows, Shift with an arrow takes a range, Delete raises the remove. A row that is one button is pressed by them, and a control in a part of the row that answers its own press (data-ui-no-row-open: a grid's chevron, its checkbox) is no stop of its own either. A table's header is a group reached by Up from the first row: Left and Right walk its captions as the columns stand, Ctrl with an arrow moves a column, Shift with an arrow sizes it, and Down goes back. A host whose rows are chosen or pressed is a listbox (rows holding no control of their own) or a grid to a screen reader; a table only read stays a table.

A bound SelectedKey under Many (or SelectedKeys under One/None) compiles with a warning (CompiledView.Warnings), logged rather than refused. Nothing prunes SelectedKey/SelectedKeys when the item they name leaves the collection — a controller that removes a chosen item clears the key itself.

Item abilities and whole-control switches

IItemAbilitiesModel — CanSelect, CanDrag, CanRemove, CanRename, CanShowContextMenu, all bool? and unset meaning "may" — lets one item opt out of what its host otherwise allows. The built-in row templates bind each to the matching property of IItemAbilitiesComponent on the row, so a flag flipped on a live item reaches its row like any other bound property.

The host-wide switches sit beside these per-item flags and gate the mechanism itself:

  • TreeComponent: Draggable, Renamable, RenameOnDoubleClick, Removable, ShowFoldChevron.
  • ItemsViewComponent and TableComponent: Draggable (moving a row among the rows, below), DragHandle and DragHandlePlacement (dragging it by a grip).
  • ItemsViewComponent, TableComponent and TreeComponent: DragKind and DragEffects (offering the rows to another host, below).
  • TabsViewComponent: Draggable (reordering by dragging captions), Renamable (the double click and F2), Removable, ShowOverflow, and TabMenuEntries (the tab menu's built-in entries, below).
  • IRowHoverableComponent.RowHoverable — whether rows highlight under the pointer, on ItemsViewComponent, TableComponent and TreeComponent alike.

Off, the control keeps no chrome for the mechanic at all — Removable = false on a tab strip means no caption shows a close and no room is kept for one, not merely that closing fails.

Moving rows

With Draggable on, a list's or a table's row whose item does not refuse it (CanDrag) is dragged and dropped between two others, or moved one place by Alt+Up and Alt+Down, whichever way the rows run. The row raises move with its key and the index it now takes, and the controller moves it — the index is what RecursiveCollection.Move takes, and in a windowed host its place in the source's whole query:

new TableComponent()
    .SetDraggable(true)
    .BindItems(nameof(Controller.Steps))
    .OnRowMoveWithItemKey(nameof(Controller.MoveStep));   // ItemsViewComponent: OnItemMoveWithItemKey

[UICommand]
public void MoveStep(string id, int index)
    => Steps.Move(Steps.IndexOf(Steps.First(step => step.Id == id)), index);

The row stands in its new place as soon as it is dropped, without waiting for the server; the command's answer says where it stays. The collection's Move of it leaves it there, or puts it where the controller did; a controller that refuses — by doing nothing, or by failing — puts it back, and so does a lost connection. A controller that orders the rows some other way (a remove and an insert, a reload) wins the same way: the page shows what the server sent.

OnRowMove/OnItemMove(command, arguments…) take the arguments by hand; UIAction.ArgEventValue(name) reads the index the event carries. A drag is refused while a sort orders the rows, which would put the row straight back, and it moves the one row dragged — a chosen group moves one row at a time. A row of a list nested in another moves within its own list, and a row of a grouped list or table within its own group: over another group's rows or a group's header no drop line shows and nothing is sent, and Alt+Up/Down at a group's first or last row does nothing. The index sent is still the collection's. The line between two rows has one place, whichever of them the pointer is over: in the middle of the gap a spacing leaves.

A row's words are not selected by default — it is pressed, not read; SetTextSelectable(true) on the list, the table or the row's template lets the reader select and copy them (see text selection). A row that drags by itself never selects, whatever the switch says — a press on it is the drag's. Where a row's words are the reader's to select and copy, or its presses to use, drag it by a grip instead:

new ItemsViewComponent()
    .SetDraggable(true)
    .SetDragHandle(UIDragHandlePlacement.Start)   // SetDragHandle(true): at the row's end
    .OnItemMoveWithItemKey(nameof(Controller.MoveStep));

DragHandle lifts a row only by the grip, at its end or, with DragHandlePlacement = Start, its start; the rest of the row keeps its presses, and its words what TextSelectable gives them. The grip is no tab stop — a press on it gives the list the keyboard on that row, and Alt+Up/Down moves the row as before. A table's grip stands in a narrow track of its own past the last column or before the first, never one of its columns, and a start grip stays pinned with a pinned first column. A wrapped items view draws no grip: its tiles drag whole.

Dragging items to another host

SetDragKind(kind) offers a list's, a table's or a tree's rows to the other components of the view as a kind — lower-case letters, digits and hyphens, "card" — and SetDragEffects says what a drop may do with them: UIDragEffects.Move, Copy, or All, the default; None offers nothing. A row whose item refuses it (CanDrag) stays; a sort, which keeps a row from moving among its own host's rows, does not keep it from leaving for another. Any component takes a kind with OnDrop(kind, command, arguments…) (OnDropLiteral for literal arguments): its command receives a UIDrop in its argument named drop, beside the arguments given — Kind, Source (the id the source was given in the view), Keys (the dragged row's, or the chosen rows' where the dragged one is chosen, in the source's order), Index (the place the first takes in a list or a table), Folder (a tree's folder, empty for its top level) and Effect. A drop between two hosts offering the same kind is a move, into anything else a copy; Ctrl (⌥ on a Mac) as it lands asks for a copy, within what the source's DragEffects allow. The keys are the page's word, not a fact: the command checks them against its own collections.

new ItemsViewComponent("todo")
    .BindItems(nameof(BoardController.Todo))
    .SetDragKind("card")
    .SetSelectionMode(UISelectionMode.Many)
    .OnDrop("card", nameof(BoardController.DropCards), UIAction.Arg("list", "todo"));

[UICommand]
public void DropCards(UIDrop drop, string list)
{
    RecursiveCollection<Card> source = CardsOf(drop.Source);
    RecursiveCollection<Card> target = CardsOf(list);
    var at = drop.Index ?? target.Count;

    foreach (var key in drop.Keys)
    {
        Card? card = source.FirstOrDefault(item => item.Id == key);

        if (card is null)
            continue;

        if (drop.Effect == UIDropEffect.Move)
            source.Remove(card);

        target.Insert(at++, drop.Effect == UIDropEffect.Move ? card : card.Copy());
    }
}

A list or a table marks the place among its rows, a tree the folder under the pointer, anything else its edge, dashed. Between two lists or tables of the kind, neither virtualized nor windowed, a move stands in the target at once and goes back unless the command's answer keeps it there; anything else waits for the server. From the keyboard, Ctrl+X (a move) or Ctrl+C (a copy) on a row — ⌘ on a Mac — takes it, or the chosen rows, and Ctrl+V on a target drops them there, after its keyboard's row in a list. The target decides as a drag's drop does, so a cut pasted into a component of another kind is a copy; Ctrl+V inside a text field is the field's own paste. A kind spelt otherwise, or one no component of the view offers, is refused when the view compiles: a drag never leaves its view.

Hosting modes

IItemsHostComponent.HostMode (ItemsViewComponent, TableComponent) is one of Plain, Virtualized, Windowed — never set directly:

  • Plain (default) — every item is real DOM, rules run over the children.
  • Virtualized() — the client holds every item's value and keeps only the rows in view (plus overscan) in the document — on a Wrap layout the lines in view, as many tiles to a line as fit it; rules run over the values and produce the projected order. Calling it on a host already bound to a source throws.
  • BindSource(path, scope) — binds to a windowed source (below) and puts the host in Windowed mode; calling it on an already-virtualized host throws, and vice versa.
  • WindowSize sets how many items one window holds (default 50); not bindable, read once by the client.
new ItemsViewComponent()
    .BindSource(nameof(Controller.Rows))
    .SetWindowSize(50)
    .FilterBy(filterBoxId, IInputComponent.ValueProperty, nameof(DemoRowItem.Title));

An items view's Padding (responsive, bindable) is room inside its scroll: the rows scroll through it, so a list ending under something laid over its foot — a composer — shows its last row clear of it, and a list held at its end stays there as the padding changes.

Windowed sources

A windowed host's items come from UIItemSourceBase<TItem>, for a collection too large to hold whole — a hundred thousand rows, a conversation read backwards. Subclass it and implement one member, GetWindowAsync, which answers a request for a window with the items in it.

  • UIItemWindowRequest carries Anchor (UIItemAnchor.Start/.End/.At(offset)/.Before(key)/.After(key), told apart by Anchor.Kind), Count, Mode (Replace or Extend, joining the read to the existing window and trimming the far side), and Query.
  • UIItemsQuery (Filters/Sorts, as UIItemFilterTerm/UIItemSortTerm) is what the host's filter/sort rules resolved to, evaluated against the controller value behind each rule's Source — a rule source must be bound on a windowed host, refused at compile time otherwise, because an unbound control lives only in the browser and the server could never see it. An inactive rule contributes no term, so an empty filter box means "everything."
  • UIItemWindow<TItem> is the answer: Items through its constructor, and the init properties Offset (where the window starts, null for a source that counts in cursors), TotalCount (under the query, null when unknown), HasMoreBefore, HasMoreAfter, optionally Aggregates over the whole query, and GroupBefore — the group of the item just before the window, which only the source knows, so a grouped host heads the window's first row only when its group differs (left null, the first grouped row is always headed). It is checked against the request: no more items than asked for, no id twice, and Offset plus the items within TotalCount.
  • UIComparisonEvaluator.Evaluate(left, operator, right) compares one value the way a filter term means it, for a source with nothing better than an in-memory scan — a source over a database translates the terms into its own query instead.

While the next window is read, an items view draws the rows it does not have yet as grey bars in the rows' shape, measured from the rows it shows, and the bars shimmer until the rows land (they stand still for a reader who asked for less motion). A source that cannot count has no room below its last row, so three such rows stand there meanwhile. For rows unlike each other — a conversation's messages, of different heights on both sides — bars would read as messages of their own: SetLoadingLook(UIItemsLoadingLook.Indicator) shows a small ring at the edge the rows come in at instead (the top while older messages load), over the rows in view, moving none of them.

A source over a database reads the count and one page of rows per request. Here OrderStore stands for the application's own data access, with CountAsync, PositionOfAsync (where a key sits under a search) and ReadAsync(search, skip, take):

internal sealed partial class OrderRow(Order order) : RecursiveObservable, IBindableItem
{
    [RecursiveMember(false)]
    public string Id { get; } = order.Id;

    [RecursiveMember]
    public partial string Customer { get; set; } = order.Customer;
}

internal sealed class OrdersSource(OrderStore store) : UIItemSourceBase<OrderRow>
{
    protected override async Task<UIItemWindow<OrderRow>> GetWindowAsync(UIItemWindowRequest request, CancellationToken cancellationToken)
    {
        // The host's one filter rule, resolved on the server; an empty filter box sends no term at all.
        var search = request.Query.Filters.Length > 0 ? request.Query.Filters[0].Value as string : null;

        var total = await store.CountAsync(search, cancellationToken).ConfigureAwait(false);

        var start = request.Anchor.Kind switch
        {
            UIItemAnchorKind.End => total - request.Count,
            UIItemAnchorKind.Offset => request.Anchor.Offset,
            UIItemAnchorKind.Before => await store.PositionOfAsync(search, request.Anchor.Key!, cancellationToken).ConfigureAwait(false) - request.Count,
            UIItemAnchorKind.After => await store.PositionOfAsync(search, request.Anchor.Key!, cancellationToken).ConfigureAwait(false) + 1,
            _ => 0
        };

        start = Math.Clamp(start, 0, Math.Max(0, total - 1));

        IReadOnlyList<Order> orders = await store.ReadAsync(search, start, request.Count, cancellationToken).ConfigureAwait(false);

        return new UIItemWindow<OrderRow>([.. orders.Select(static order => new OrderRow(order))])
        {
            Offset = start,
            TotalCount = total,
            HasMoreBefore = start > 0,
            HasMoreAfter = start + orders.Count < total
        };
    }
}

request.Query.Sorts is the host's SortBy rules in the same way, for the query's ORDER BY.

The UIItemSourceBase<TItem> protected helpers — Append, Prepend, Remove, Invalidate — mutate the realized window and its TotalCount/HasMoreBefore/HasMoreAfter bookkeeping directly; there is no event to raise, changing Items is the change notification. A source is itself RecursiveObservable and typically lives as a [RecursiveMember(false)] property on the controller, which reads the first window in OnInitializeAsync so the page paints with rows already in it — the client reads further windows itself as the user scrolls, but nothing paints before the first read completes:

internal sealed partial class OrdersController(OrderStore store) : UIControllerBase
{
    [RecursiveMember(false)]
    public OrdersSource Orders { get; } = new(store);

    protected override Task OnInitializeAsync(CancellationToken cancellationToken)
        => Orders.LoadWindowAsync(new UIItemWindowRequest(UIItemAnchor.Start, 50), cancellationToken);
}

A command jumps the same way — Orders.LoadWindowAsync(new UIItemWindowRequest(UIItemAnchor.At(5_000), 50), ...) replaces the window, and Orders.Offset/Orders.TotalCount say where it landed.

A page at a time

A windowed host that says SetPaging(true) (Paging, bindable) shows its window as a page of WindowSize rows: its scroll asks for nothing, and a PagerComponent aimed at it by id turns the page — through the same window request the scroll makes, by offset. The pager shows the pages by number (UIPagerMode.Full: first, previous, the ends and the pages around the current one with an ellipsis for the rest, next, last) or the rows on show (Compact: "21–40 of 812" between previous and next); on a phone it is compact whatever its mode. SetPageSizes([20, 50, 100]) offers the viewer a size, kept in the browser under the list's id, as a table keeps its columns' widths, so a reload lands on it; a size no longer offered is ignored. Page Up and Page Down in the list turn its page too.

new ItemsViewComponent("results")
    .BindSource(nameof(SearchController.Results))
    .SetWindowSize(20)
    .SetPaging(true)

new PagerComponent()
    .SetTarget("results")
    .SetPageSizes([20, 50, 100])

A pager aimed at nothing, at a component the view does not have, at a host that holds its rows whole or at a window that scrolls is refused when the view compiles. The page lives in the source (Offset); an application that wants it in the address writes it from there — Context.SendEffectsAsync([new ReplaceAddressEffect(...)]) as the source reads a page — and reads it back in OnNavigatedAsync, loading that page's window before the page draws.

The table's columns

TableComponent.AddColumn(caption, template, width, alignment, key, pinned, icon, hidden) registers a UITableColumn and a template variant keyed column:{key} (key defaults to a 1-based ordinal). AddTextColumn(caption, propertyPath, width, alignment, key, pinned, icon, hidden) is the shorthand for a text cell, binding a DefaultTextTemplate relatively to the row. A pinned column stays fixed while the table scrolls sideways, and pinned columns must lead. An icon (UITableColumn.Icon, and IconColor through SetColumnIcon(key, icon, color)) stands before the caption, in the header and beside a sort mark, while the column's accessible name stays the caption. A hidden column (UITableColumn.Hidden, HideColumn(key)) starts hidden at every width; a viewer's own choice in a column chooser, kept in the browser, wins over it. A plain table draws no chooser, so only a host with one — the data grid — can show such a column again. HideColumnBelow(key, tier) hides a column below a viewport tier:

new TableComponent()
    .SetItems(rows)
    .AddTextColumn("Service", nameof(DemoDeploymentRow.Service))
    .AddTextColumn("Replicas", nameof(DemoDeploymentRow.Replicas), UIGridUnit.Absolute(96), UITextAlignment.End)
    .AddColumn("Status", badgeTemplate, UIGridUnit.Absolute(120));

Columns is read-only and render-time only (IsBindable = false) — the columns are how the table is built, not state. ShowHeader, Striped, ShowColumnSeparators, ShowRowSeparators, ResizableColumns (client-side only; widths are never sent back; from the keyboard, Shift with an arrow on a caption) and ReorderableColumns (a column dragged by its caption; the order stays client-side too, and pinned columns keep their place) round out the table's own switches. Sorting by header and editing are not built in; a page at a time is the pager's (A page at a time, above).

A column's template may hold a list of its own — an items view bound relatively to a collection on the row — and each row shows its own row's items.

The tree

TreeComponent renders ITreeNodeModel rows — a text item plus ParentId, Kind, HasChildren, IsFolder, Expanded, DropTarget — as a flat, keyed list in walking order, not a nested structure. TreeNode (the built-in model) and TreeNode.Flatten(roots, children, toNode) turn a nested source into that list, stamping ParentId on the way down.

  • Kind picks a node template variant added with AddNodeKind(kind, template); ConfigureDefaultNode/ SetNodeTemplate shape the one used when no variant matches.
  • OnNodeClick/OnNodeClickWithItemKey/OnNodeClickWithItem/OnNodeClickWith run a command on a press on a node — the row's click, as OnItemClick is a list's — after the selection has followed the press, so a notes tree opens a note on one press (a phone has no double click) and answers with effects like any command. A press on the chevron only folds, and a press inside an open rename field is the field's. From the keyboard, Enter on a node runs its click and then its open (OnNodeOpen…), as on an items view's or a table's row, and Space chooses — or, in a tree that chooses nothing, runs the click; Right and Left fold.
  • An empty tree — or one whose every node a filter leaves out — draws its empty template (SetEmptyTemplate, or ConfigureDefaultEmptyTemplate to word the built-in one, which a table has too), and takes it out when a node comes back. SetShowEmptyTemplate(false) (bindable; on the items view and the table too) shows nothing instead — a short list under every row of a feed need not say "nothing" under each; the template is hidden, not left out.
new TreeComponent("notes-tree")
    .BindItems(nameof(NotesController.Nodes))
    .SetSelectionMode(UISelectionMode.One)
    .BindSelectedKey(nameof(NotesController.SelectedNodeKey))
    .ConfigureDefaultEmptyTemplate(empty => empty.SetTitle("No notes yet."))
    .OnNodeClickWithItemKey(nameof(NotesController.OpenNodeAsync))
  • HasChildren lets a node claim children before any are in the list; OnNodeUnfold/OnNodeUnfoldWithItemKey fire the first time it is unfolded, and the controller answers by adding the children or clearing the flag.
  • Renamable/RenameOnDoubleClick plus a node's own CanRename gate F2/double-click renaming; a rename writes the new title back through the node's own two-way Title binding, and OnNodeRename/ OnNodeRenameWithItemKey fire afterward for refusing or normalizing it.
  • Draggable plus a node's CanDrag gate dragging a node onto a folder, between two nodes or onto the tree's own ground, or moving it with Alt and an arrow; the move writes DropTarget and raises OnNodeMove/OnNodeMoveWithItemKey with the index it takes among that folder's nodes, and the controller moves the node or leaves it — nothing moves on the client on its own. A folder is a node with IsFolder = true — even while empty, without asking for its children — or, unmarked, one holding children; IsFolder = false takes no drop whatever it holds. Over a file, the dragged node, a node under it or a disabled folder, the cursor says no drop and a release sends nothing. A tree with a DragKind offers its nodes to another host even without Draggable, a folder going with what it holds.
  • A node that says whether it is a folder (IsFolder true or false) and names no Icon of its own is dressed as a file tree's: a folder, open while unfolded, in a golden yellow, or a page in the title's ink; its own Icon, or an IconColor other than the default, wins.
  • Indent sets how far each level steps in, in pixels; ShowFoldChevron toggles the chevron for a node that can unfold — off, the arrows still fold, and a press folds only a node that cannot be chosen.

Items hosts beyond lists

MenuComponent renders IMenuItemModel entries with Kind selecting header/separator/check/select/plain variants (a check shows Checked as a mark at its end, a select shows Value and opens its Items beside it), an entry's Items as a nested menu one level deep, and folds to icons alone via ICollapsibleComponent. SetToggleContent puts content beside its switch, seen only while it is open, and SetSearch a search there that narrows the entries in the browser by the words they show, nested ones included; a search that leaves nothing shows the menu's empty template, "Nothing to show." unless the menu has its own. A MenuItem is a TextItem, so an entry carries a Description — one muted line under its title, cut with an ellipsis, the icon centred across both — as a contact list's last message; an entry's Icon may be a picture's address, and IconShape = UIIconShape.Circle draws it round, as a person's avatar is (a glyph keeps its own shape; every item model and text body carries IconShape, and ImageComponent.SetShape(UIImageShape.Circle) is a standing picture's). Folded, a menu keeps its entries' badges on their icons' corners and its entries' names: a direct entry's title is its tooltip, on hover and on the keyboard's focus, unless it has a tooltip of its own. SetDisplay(UIMenuDisplay.Rail) draws the menu as a navigation rail instead — a narrow column, each entry its icon over a one-line label, its badge on the icon's corner (an empty BadgeText a dot), the current entry marked by a bar on the rail's edge and its icon filled, the ground the menu's Surface; a label cut short shows whole as its tooltip. A rail never folds and draws no toggle, its groups fly out beside it as a folded menu's do, and it takes no search, since a match inside a group would not show; its entries stand edge to edge. SetSize picks its measures, Medium unless set: Large a 72 px column of 24 px glyphs over caption-size labels, Medium 60 px of 20 px glyphs over smaller labels, Small 48 px squares whose labels are only their tooltips (and still the entries' names to a screen reader). Laid out horizontally, it is a bottom navigation bar, its entries sharing its length down to a press's width each — 64, 56 or 48 px by the size — and then scrolling sideways, a caption or a rule between them an upright line. A rail that is the whole of a view's left side is the navigation rail on a wide screen and that bottom bar on a phone: where the sides become drawers (UIViewOptions.SideDrawers, below the medium breakpoint), a left side holding the rail and nothing else — the rail itself, or containers, stack or wrap panels, surfaces and scroll containers each holding only the next one down to it — is no drawer and gets no button; the rail lies along the page's bottom, the current entry marked on its top edge over the bar's hairline, its groups flying out upward, Left and Right walking it, and the content and footer end above it. A side holding anything more, a list menu, a rail whose Display is bound, and a right side stay drawers.

protected override IVisualComponent? CreateLeftSide()
    => new ContainerComponent()
        .SetPadding(UIThickness.All(8, 0, 4, 16))
        .AddChild(new MenuComponent("sidebar")
            .SetDisplay(UIMenuDisplay.Rail)
            .BindItems(nameof(ShellController.Navigation)));

A group's flyout, and a hidden or cut title's tooltip, open toward the content — to the right of a menu on the left, to the left of one on the right, above a bottom bar. A group's own entry, in any menu, only opens and closes its group: it raises no item click, so a command belongs on the entries inside it. TabsViewComponent renders ITabItemModel entries sorted by Order, with a two-way SelectedKey for the open page — its pages come from the collection, unlike TabsComponent, whose captions are fixed regions the view authors directly and which is not an items host at all.

A right press on a tabs view's caption — or the context-menu key on a focused one — opens the strip's own tab menu. Its built-in entries are the ones TabMenuEntries chose (UITabMenuEntries, flags, bindable; None by default, so a strip offers none unless asked):

  • Rename — the same field a double click opens, whether or not the strip is Renamable (that switch governs the double click and F2); an item's CanRename = false still refuses it.
  • Pin — shown as Pin or Unpin by the tab's state: the tab's two-way Pinned, the tab moved to the end of the pinned ones and its new Order written back as a drop writes it.
  • Close or Delete — the two forms of the one remove entry, chosen one or the other (SetTabMenuEntries refuses both): Close is neutral, with the cross; Delete wears the trash glyph in the danger colour. Either does exactly what the cross does, so it shows only where OnItemRemove hangs a command and the tab may go — never on a pinned tab.

An application's own entries go in with AddTabMenuEntries, and OnTabMenuEntry hears them with the entry's key and the tab's. The order is fixed — Rename, Pin or Unpin, a rule, the application's entries and a rule, the remove entry last — and a rule shows only where entries show on both sides of it; a menu with nothing to offer a tab stays shut.

new TabsViewComponent()
    .BindItems(nameof(EditorController.Documents))
    .SetTabMenuEntries(UITabMenuEntries.Rename | UITabMenuEntries.Pin | UITabMenuEntries.Close)
    .AddTabMenuEntries(new MenuItem { Id = "close-others", Title = "Close others" })
    .OnTabMenuEntry(nameof(EditorController.TabAction))      // TabAction(string entry, string id)
    .OnItemRemove(nameof(EditorController.CloseDocument))

A tab template given a context menu of its own (SetContextMenu) keeps full control: its menu replaces the strip's, and the strip draws none.

SelectComponent, SearchComponent and RadioGroupComponent extend OptionsInputComponentBase<TComponent, TItem>, whose value is one option's key, and MultiSelectComponent its sibling over a value of its own, OptionsInputComponentBase<TComponent, TItem, TValue> — an IReadOnlyList<string> of the chosen keys in the order they were chosen, each once. AddOption/AddOptions/SetOptions/BindOptions are the option-flavoured names for AddItem/AddItems/SetItems/BindItems, over IOptionModel items. The select and the multi-select share their field — clear button, chevron, placeholder, where the list opens, appearance, size, caption and affixes — through SelectComponentBase<T, TItem, TValue>; the multi-select draws each chosen option as a chip with its own remove button, checks the chosen ones in a list that stays open while they are toggled, and caps the value with MaxSelected. Its chips are reached from the keyboard: ArrowLeft from the field walks onto them, and Delete or Backspace takes one out.

SetAllowFreeText() lets the reader type values of their own — labels, recipients, keywords. An entry stands after the chips: Enter or a comma makes a chip of its text, a pasted "a, b, c" makes three, and Backspace on an empty entry takes the last chip. The options become suggestions, narrowed as the reader types; an arrow picks one, and Enter otherwise takes the text — or, with SetTagEntry(UITagEntry.FirstSuggestion), the first suggestion is marked as the reader types and Enter takes it, the text only where none matches (Escape takes the mark off). A typed tag naming an option is that option's key, any other is its own text, and the value is the same list of strings. A rule every tag must match is RegexEach; a tag it refuses, or one past MaxSelected, stays in the entry and is said on the field's line:

new MultiSelectComponent()
    .SetTitle("Labels")
    .SetAllowFreeText()
    .SetOptions(KnownLabels)
    .SetMaxSelected(5)
    .RegexEach(@"^[^\s,]{2,24}$", "A label is 2 to 24 characters, with no spaces.")
    .BindValue(nameof(TicketController.Labels))

A SearchComponent over its own options narrows them in the browser as the menu's search does — every typed word, in any order, case and accents aside, must appear in an option's name — and a group's header goes with the last of its options. A search with an OnSearch answer narrows nothing itself: its list stands until the answer and then shows exactly what the server sent. Closed, a search is a select's field and shows the chosen option; open, its text field stands pinned at the top of the list. The term stays between openings, selected as the list opens, and a pick closes the list with the keyboard back on the field, which shows the value.
